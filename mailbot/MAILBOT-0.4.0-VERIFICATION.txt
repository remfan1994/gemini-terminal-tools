ttychatter.mailbot 0.4.0 verification
=======================================

Artifact set
------------
- ttychatter.mailbot
- ttychatter.mailbot.1
- README
- MAILBOT-WALKTHROUGH
- CHANGELOG

Base
----
- Built from the 0.3.4 mailbot script so the 0.3.3/0.3.4 config-path,
  config-parser, --raw-config, cron/PATH, and diagnostics changes are retained.

Syntax target
-------------
Canonical control subjects:
- tc:CONFIG
- tc:MODELS
- tc:CMD
- tc:command args

Canonical chat subjects:
- tc:{session-name}
- tc:{new}

Legacy compatibility still accepted:
- tc:{CONFIG}
- tc:{MAILBOT}
- tc:{MAILBOT:command args}

Script checks run
-----------------
- python3 -m py_compile ttychatter.mailbot
- ttychatter.mailbot --version
- ttychatter.mailbot --help
- ttychatter.mailbot --manpage
- ttychatter.mailbot --config
- ttychatter.mailbot --update-models --dry-run
- ttychatter.mailbot --sessions

Parser/function checks run
--------------------------
The following subjects were routed successfully:
- tc:CONFIG -> config
- Re: tc:CONFIG -> config
- tc:MODELS -> command update-models
- tc:models -> command update-models
- tc:model-list --all -> command model-list --all
- tc:models --all -> command models --all
- tc:CMD -> command from body or help when body is empty
- tc:CMD search foo -> command search foo
- tc:CMD:search foo -> command search foo
- tc:sessions -> command sessions
- tc:{alpha} -> session alpha
- tc:{new} -> session new
- tc:{CONFIG} -> legacy config
- tc:{MAILBOT:sessions} -> legacy command sessions
- tc:{MAILBOT} -> legacy command from body or help when body is empty

The tc:{new} chat path was checked against a fake ttychatter command. The
mailbot invoked ttychatter with only --loopback and no session argument, which
lets ttychatter.python create its own default timestamped session name.

Manpage/docs consistency
------------------------
- --manpage reports ttychatter.mailbot 0.4.0.
- README, MAILBOT-WALKTHROUGH, CHANGELOG, and ttychatter.mailbot.1 document the
  canonical 0.4 subject grammar.
- Legacy braced control subjects are documented only as compatibility aliases.
- MODELS_SUBJECT_TOKEN and COMMAND_SUBJECT_TOKEN are present in config parsing,
  --config output, and docs.

ASCII check
-----------
ASCII plaintext check passed for:
- ttychatter.mailbot
- ttychatter.mailbot.1
- README
- MAILBOT-WALKTHROUGH
- CHANGELOG
